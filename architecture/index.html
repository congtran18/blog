"We split the platform into 4 clean layers:

Second, the Fast Ingestion Engine built in Go. It catches bank webhooks in 4.2ms, verifies cryptographic signatures across multi-core goroutines, and locks Redis to prevent double payment.

Third, the Workflow & AI Brain using Temporal. It coordinates clearing flows across 14 countries and runs Gemini Flash to read messy tax documents in 258ms.

PHASE 1 PHA 1
Session Initialization & Dynamic QR Generation (Edge Gateway • 45ms): The customer selects the shipment (Bill of Lading) to release. The portal calls APISIX, validates the token in 0.02ms, and calls domestic bank rails to generate a dynamic QR code with the exact amount and unique reference. The customer scans the code on mobile banking, and money transfers directly into ONE's company bank account within seconds. Khởi tạo thanh toán & Tạo mã Dynamic QR (Edge Gateway • 45ms): Khách hàng chọn vận đơn (Bill of Lading) cần nhả container. Portal gửi request qua APISIX, xác thực token trong 0.02ms và gọi trực tiếp ngân hàng tạo Dynamic QR code chứa số tiền chính xác và mã PO duy nhất. Khách hàng quét mã trên Mobile Banking, tiền chuyển thẳng vào tài khoản ngân hàng của hãng tàu trong vài giây.
PHASE 2 PHA 2
Bank Webhook Ingestion & Distributed Mutex Lock (Go Broker • 4.2ms): The bank fires an HTTP POST webhook. APISIX routes it to the compiled Go Broker. Go validates the x.509 RSA signature in 0.8ms on native goroutines and executes an atomic MSETNX lock:payment:{invoice_id} in Redis (TTL 30s). Returns HTTP 200 OK to the bank in 4.2ms flat and asynchronously dispatches a gRPC task to Temporal, strictly preventing double-spending. Bắt Webhook ngân hàng & Khóa Distributed Mutex (Go Broker • 4.2ms): Ngân hàng gửi webhook báo có. APISIX chuyển tiếp thẳng vào Go Webhook Broker. Go dùng goroutine xác thực chữ ký RSA x.509 trong 0.8ms và thực thi atomic lock MSETNX lock:payment:{invoice_id} trên Redis (TTL 30s). Nếu thành công, trả ngay 200 OK cho ngân hàng trong 4.2ms và bắn tín hiệu gRPC vào Temporal queue, triệt tiêu 100% rủi ro khách hàng quét đúp hoặc ngân hàng bắn webhook lặp.
PHASE 3 PHA 3
AI FinOps Tax Extraction & SAP Code Matching (258ms): If Withholding Tax (WHT) or port fee receipts are attached, Temporal triggers the AI pipeline: C++ PyMuPDF/OpenCV straightens and optimizes scanned PDFs in 18ms (compressed to 280KB, fitting 4 vision tiles); Gemini 1.5 Flash extracts tax details in 258ms using prompt templates cached in Vertex AI RAM (cutting token costs by 77%); Redis Vector HNSW search matches local fee descriptions to standard SAP tax codes in 1.2ms. AI FinOps trích xuất thuế & Khớp mã SAP (258ms): Nếu đơn hàng có chứng từ khấu trừ thuế (WHT) hoặc phí cảng phụ thu, Temporal gọi AI FinOps pipeline: C++ PyMuPDF/OpenCV tiền xử lý ảnh trong 18ms (nén còn 280KB vừa vặn 4 vision tiles); Gemini 1.5 Flash trích xuất dữ liệu trong 258ms nhờ 3,200 token prompt được cache sẵn trên RAM Vertex AI (tiết kiệm 77% chi phí); Redis Vector HNSW map mô tả phí địa phương ("phí lưu bãi", "THC") sang mã điều kiện SAP chuẩn trong 1.2ms.
PHASE 4 PHA 4
ERP SAP FI-AR Clearing & Instant e-D/O Port Release (< 60s): Temporal workflow calls SAP S/4HANA FI-AR via RFC/OData to post accounts receivable clearing. Upon receiving SAP 200 OK and accounting document ID, Temporal immediately calls port Terminal Operating System (TOS) APIs (Cat Lai, Laem Chabang). TOS issues an Electronic Delivery Order (e-D/O) with an encrypted barcode to the truck driver, allowing gate-out in under 60 seconds without counter paperwork! Gạch nợ ERP SAP & Cấp lệnh giao hàng điện tử e-D/O (< 60s): Temporal workflow kích hoạt activity gọi SAP S/4HANA FI-AR qua RFC/OData để gạch nợ hóa đơn. Ngay khi SAP phản hồi 200 OK kèm số chứng từ kế toán, Temporal lập tức gọi API hệ thống quản lý cảng (TOS - Cat Lai, Laem Chabang). TOS tạo lệnh giao hàng điện tử (e-D/O) kèm mã QR bảo mật gửi về điện thoại tài xế container. Xe container qua cổng cảng lấy hàng ngay lập tức mà không cần tài xế phải cầm hồ sơ giấy xếp hàng tại quầy kế toán!

Compiled Go Broker vs. Node.js Ingestion Viết Go Broker vs. Dùng Node.js cho Webhook Go worker pool running native CPU crypto/rsa verification with zero runtime GC pauses; 4.2ms flat. Golang chạy đa luồng CPU giải mã chữ ký RSA trong < 1ms, không bao giờ bị nghẽn event loop, phản hồi chuẩn 4.2ms. Node.js single-threaded event loop: RSA verification starved CPU, pushing p99 latency to 3.8s and causing bank retry storms. Node.js chỉ có 1 thread chính, giải mã RSA tốn CPU làm đơ cả server, độ trễ vọt lên 3.8s khiến ngân hàng tưởng lỗi và bắn dồn dập.
Saga Orchestration vs. 2PC Across ERP Dùng Saga (Temporal) vs. 2PC trên SAP ERP Temporal Sagas with asynchronous compensating transactions and exponential backoff. Temporal Saga chạy bất đồng bộ với các bước bồi hoàn tự động (Compensating Actions), chịu được mạng chập chờn xuyên quốc gia. Distributed 2-Phase Commit (2PC): Held row-level database locks across WAN, crashing during SAP maintenance windows. 2-Phase Commit (2PC): Giữ khóa dòng database qua mạng WAN, chỉ cần SAP bảo trì là toàn bộ hệ thống bán hàng bị treo cứng.
Redis Vector HNSW vs. pgvector / Elasticsearch Redis Vector (HNSW) vs. pgvector / Elasticsearch Redis in-memory HNSW index returning top-1 cosine matches in 1.2ms with zero disk I/O. Redis index thuật toán HNSW trực tiếp trên RAM, trả kết quả so sánh cosine trong 1.2ms không tốn I/O đĩa. pgvector / Elasticsearch: 45ms–120ms cold-start query latency, causing downstream invoice clearing backpressure. PostgreSQL / Elasticsearch: Độ trễ truy vấn vector tốn 45ms–120ms, làm nghẽn dòng xử lý hóa đơn tự động.
Bounded maxPoolSize=15 vs. Default 100 Giới hạn maxPoolSize=15 vs. Để mặc định 100 Strictly bounded pool size preventing MongoDB WiredTiger 128-ticket saturation across 30 GKE pods. Khống chế tổng số kết nối dưới 450 sockets, giữ số luồng hoạt động dưới 50 để không làm nghẽn 128 vé đọc/ghi của WiredTiger. Driver defaults (100): 3,000 active sockets choked WiredTiger engine, spiking read/write latency to 4.8 seconds. Cấu hình mặc định (100): 30 Pod tạo ra 3,000 sockets tranh giành 128 vé của MongoDB, khiến độ trễ nổ tung lên 4.8 giây.
Keyset Pagination vs. Offset skip() Phân trang Keyset vs. Dùng skip(N) Deterministic cursor _id < last_seen_id; returns in 1.62ms flat at 25.4 million records. Duyệt con trỏ O(1) theo _id < lastSeenId; trả kết quả trong 1.62ms phẳng trên bảng 25.4 triệu dòng log. Offset-based skip(N): O(N) B-tree traversal taking 5.4 seconds at page 50, triggering HTTP 504 gateway timeouts. Dùng skip(N): MongoDB phải quét lại từng dòng từ đầu bảng, ở trang thứ 50 mất tới 5.4 giây gây lỗi HTTP 504 Timeout.
Double HttpOnly Cookies vs. LocalStorage Double HttpOnly Cookie vs. Lưu LocalStorage __Host- prefixed cookies with SameSite=Strict; 100% immune to XSS token theft. Cookie có cờ __Host- và SameSite=Strict; JavaScript không đọc được, miễn nhiễm 100% với hacker trộm token XSS. LocalStorage / SessionStorage: Vulnerable to third-party script injection and malicious npm dependency exploits. LocalStorage / SessionStorage: Bất kỳ thư viện npm độc hại nào cũng có thể đọc trộm JWT token và giả mạo lệnh xuất kho container.
Apache APISIX vs. NGINX Ingress Reload Apache APISIX vs. NGINX Ingress Reload APISIX with etcd dynamic watchers; zero worker reloads during Kubernetes pod autoscaling spikes. APISIX dùng etcd watch đồng bộ bảng định tuyến vào RAM; Pod tự động scale liên tục mà không cần reload worker process. NGINX Ingress: Worker process reload on upstream pod changes caused dropped WebSocket packets and 502 Bad Gateways. NGINX Ingress: Mỗi lần Pod scale là reload worker, gây rớt gói tin WebSocket và sinh lỗi HTTP 502 Bad Gateway trong giờ cao điểm.
